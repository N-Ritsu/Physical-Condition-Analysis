# Physical-Condition-Analysis

就労移行支援向け 体調・睡眠分析ダッシュボード。日報Excelから入眠時間・起床時間・睡眠の質・中途覚醒回数・気分を抽出してグラフ化し、即時のルールベース解説＋任意のローカルLLM（Ollama）による詳しい解説を表示するStreamlitアプリ。

設計の背景は [docs](docs/) 内のヒアリング議事録・課題定義書・要件定義書・ワイヤーフレームを参照。

## セットアップ

```bash
pip install -r requirements.txt
```

ローカルLLMを使う場合はOllamaをインストールし、モデルを取得しておく。

```bash
ollama pull qwen3:8b
```

## データ配置

- `data/日報データ.xlsx`: 日報Excel（列: 日付・就寝時間・起床時間・睡眠の質・気分（起床時）・気分（通所時）等）。ファイルが無い場合、アプリ起動時にアップロード画面が表示される。
- `data/オリジナルセルフケアシート .xlsx`: 月ごとにシートが分かれたセルフケアチェック表（〇/△/✕）。グラフのマーカー（○/△/×＝体調）はこのファイルから計算する。ファイルが無い場合、マーカーはすべて「記録なし（早退等の可能性）」として黒い×で表示される。

個人の健康データのため `data/*.xlsx` は `.gitignore` 済み。

streamlit run app.py

## データ解釈に関する注意（実データの制約に基づく調整）

- **入眠時間**: 元データには「就寝時間」列のみ存在し、9〜11時台の値はAM/PM区別なく記録されている（例: 実際は21:30就寝でも `09:30` と記録）。そのため6〜11時台の値はPM（+12時間）として正規化している（[data_loader.py](src/health_dashboard/data_loader.py) の `normalize_bedtime`）。
- **中途覚醒回数**: 独立した列がなく、「睡眠の質」列の自由記述（例: `悪い, 中途覚醒３以上`）から抽出している。「３以上」は3として扱い、「早朝覚醒」の記載は中途覚醒回数に+1として合算する。睡眠の質評価が複数併記されている行は、より悪い方（良好<普通<悪い）を採用する。
- **気分**: 「気分（起床時）」「気分（通所時）」の2系列があるため、縦軸の選択肢として両方を用意している。
- **体調マーカー（○/△/×）**: セルフケアシートの「睡眠・食事・ストレス」「良好サイン」「注意サイン」「悪化サイン」「回復対処」の全チェック項目（備考欄を除く）を、〇=0点・△=1点・✕=2点として日ごとに合算し、0点=○良好／1〜2点=△普通／3点=×注意／4点=×警戒／5点以上=×異常の5段階に変換している（[data_loader.py](src/health_dashboard/data_loader.py) の `CONDITION_CAUTION_POINTS` / `CONDITION_WARNING_POINTS` / `CONDITION_ABNORMAL_THRESHOLD`）。3〜5点の区切りは実データの分布（0点の日を除くと1〜4点に集中し、7点以上は明確な外れ値）に基づく初期値で、現場の実感に応じて調整可能。日報はあるがセルフケアシートに記録がない日は、早退等により記入できなかった可能性を示すサインとして黒い×で表示する。

## 振り返りコメントの生成方式（ハイブリッド）

ローカルLLM（qwen3:8b）はCPU環境では生成に数十秒〜数分かかることがあり、日々グラフを確認する用途には不向きなため、2段構成にしている。

1. **既定表示（即時・LLM不使用）**: 統計値（平均・直近値・前半後半のトレンド）を条件分岐だけで文章化する（[rule_based_insight.py](src/health_dashboard/rule_based_insight.py)）。待ち時間ゼロで、文面が事前に固定されているためガードレールも構造的に保証される。
2. **AIによる詳しい解説（任意・ローカルLLM）**: 折りたたみ内のボタンから、より自然な文章の解説をOllama（qwen3:8b）で生成する（[llm_insight.py](src/health_dashboard/llm_insight.py)）。面談前など、時間に余裕がある場面向け。

いずれも支援員が医療職ではないことを前提に、以下を厳守する。

- 医学的診断・病名判断・服薬に関する言及をしない。
- 断定的な因果関係を主張しない。
- 「〜の傾向が見られます」「面談で聞いてみませんか」という対話補助のトーンに限定する。
- すべての処理はローカルで完結し、外部送信は行わない（LLMもクラウドAPIではなくローカルのOllamaにのみ問い合わせる）。
