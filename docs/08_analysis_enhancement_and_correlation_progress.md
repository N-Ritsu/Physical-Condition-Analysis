- 作成日: 2026年9月17日
- 位置づけ: `05_prototype_creation_progress.md`（ローカルLLMの不採用まで）に続く記録として、その後に実施したルールベース振り返りコメントの高度化・日付表示の統一・相関表機能の追加をまとめる。`05`と同様、設計文書自体の更新ではなく対応記録として扱う。

## 1. 概要

`05`でローカルLLMを不採用とし、条件分岐のみによる振り返りコメント生成に一本化した後、その条件分岐の中身を大きく拡充した。あわせて、グラフの日付表示の見づらさを解消し、`07_correlation_table_image.jpg`のワイヤーフレームに基づく相関表機能を新たに追加した。

## 2. 振り返りコメント（ルールベース分析）の高度化

`05`時点の振り返りコメントは、平均・直近値・前半後半のトレンドを条件分岐で文章化するだけの単純なものだった。以下の分析を段階的に追加している（[rule_based_insight.py](../src/health_dashboard/rule_based_insight.py)）。

- 前半後半の平均比較を、線形回帰の傾き（trend_diff）と決定係数（R²）による判定に置き換えた。傾きの符号と大きさで増減を判定し、R²が低い（ばらつきが大きい）場合は「目安としてご覧ください」と留保を付ける。
- 軸ごとに「良し悪しの方向性」（`AXIS_DIRECTION`: 方向性なし／少ないほど良い／多いほど良い）を定義し、トレンドの増減を「良い方向」「注意したい方向」と評価するようにした。
- 直近値のzスコアによる外れ値検知を追加した。方向性のある軸では、悪化方向の外れ値のみを注意対象とする（例: 気分が急に大きく上がった場合は警告しない）。
- 体調（セルフケアシート由来）が「注意」以上の状態が続いている場合のストリーク検知を追加した。選択中の軸に関わらず評価する。
- 期間内の安定度比較を追加した。「全期間」表示では4週間単位、「直近1ヶ月」表示では1週間単位でローリング集計し、最も安定していた期間・最も不安定だった期間を検出して直近の期間と比較する。
- 安定度比較には実装中に不具合が見つかった。窓ごとの標準偏差の差が小さくても、値の取りうる幅が狭い軸（睡眠の質など）では常にジグザグしていて実際には落ち着いた時期がないケースを「安定」と誤判定していた。最も安定していた窓自体の標準偏差がしきい値を超えている場合は「期間を通して常に不安定」と判定する分岐を追加して解消した。あわせて、窓同士の比較では「安定」と出ているのに直近だけ単独でばらつきが大きく、締めの文言だけが注意喚起になるという矛盾も見つかり、直近ウィンドウの絶対的なばらつきを説明文側にも反映させて解消した。
- 安定度（ばらつき）とは別に、期間内の水準（値そのものの良し悪し）比較を追加した。「最も安定していた期間」が必ずしも「値が最も良かった期間」とは限らないため（例: 中途覚醒回数が一定して2回だった期間より、ばらつきはあっても0回に近い期間の方が良い）、安定度比較とは別の文で言及する。方向性のない軸（入眠時間・起床時間）では評価しない。
- 「直近1週間」表示は期間内比較ができるほどデータがないため、直近2日分の値を軸ごとの絶対的な良し悪し基準（睡眠の質は「悪い」カテゴリ、中途覚醒回数は3回以上、気分は5未満。トレンドや平均とは無関係）で評価する方式を別途追加した。
- 締めの一文を、分析結果に応じて3パターンに出し分けるようにした。直近に悪化傾向・外れ値・体調ストリーク・不安定期や悪い水準の期間への接近・直近数日の絶対的な悪化のいずれかがあれば注意喚起、直近は問題ないが期間内の差が大きければ自己分析を促す、どちらでもなければ安定している旨を伝える、の3分岐。締めの文言も「注意して見ていくとよいかもしれません」から「気にかけてあげたほうが良いかもしれません」という支援員向けアドバイス形式に変更した。
- 上記の複数の分析結果を1つの文章にまとめる際、安定度比較（どの期間が安定/不安定だったか）→水準比較（どの期間の値が良かった/悪かったか）→安定度比較の直近との比較、という順に並べ替えた。安定度と水準の説明が離れていると読みにくいとの指摘を受けての対応。

## 3. 日付表示の統一

「全期間」表示のグラフで、横軸の日付がPlotlyの既定表示だとデータ点の間隔に依存して不規則に見える問題があった。各月の1日・15日を目盛りにする独自の目盛り設定を追加した（[app.py](../app.py) の `_apply_date_axis_ticks`）。該当日がほとんど無い短い期間（直近1週間等）では既定表示のままにする。

これに合わせて、グラフのホバー表示・直近1週間や直近1ヶ月表示の横軸・振り返りコメント文中の日付表記（例:「7月23日」）も、すべて「月/日」形式（例:「7/23」）に統一した。振り返りコメント側の日付整形関数は `_format_date_jp` から `_format_date_md` に改名している。

## 4. 相関表機能の追加

`07_correlation_table_image.jpg` の手描きワイヤーフレームに基づき、6指標（入眠時間・起床時間・睡眠の質・中途覚醒回数・気分（起床時）・気分（通所時））間のピアソン相関係数を色分け表示する機能を追加した。

- サイドバーの「期間」の下に「表示」（グラフ／相関表）を追加し、メイン画面を切り替える方式にした。相関表は常に全期間のデータで算出し、サイドバーの縦軸・期間の選択には影響されない。
- しきい値は｜r｜≥0.6を赤（相関が強い）、0.3〜0.6を黄（相関がありそう）とした。相関係数の算出自体は `stats.py` に `correlation_matrix` を追加して行う（対角線とデータ不足のペアはNaN扱い）。
- 実装中、`st.dataframe` にStylerを渡すと、対角線などのNaNセルがStreamlit側の独自表示（"None"）で上書きされ、Styler側で指定した `na_rep="―"` が反映されないことが分かった。対話型グリッドではなく、Stylerを静的HTMLとして描画する `st.table` に切り替えて解消した。

## 6. 現状の制約・今後の課題（更新）

- 体調ポイントの閾値・相関のしきい値（0.6 / 0.3）はいずれも初期値であり、現場の実感に応じた調整の余地がある。
- 相関表は数値上の関連を示すのみで、因果関係や医学的な意味づけは行わない旨を画面上に明記しているが、支援員・利用者への説明（研修等）が別途必要になる可能性がある。
- ヒアリングで挙がっていた"季節性"を意識した長期（半年〜1年）比較のUIは未実装で、現状は直近1週間・直近1ヶ月・全期間の3種のみ。（利用者のデータは１年未満になっていることが多く、実装は難しいかもしれない）
- 複数利用者対応についても、現在は1人分のデータを前提とした構成であり、就労移行支援事業所での複数利用者運用を想定する場合、利用者切り替えUIなどが今後必要になる。
